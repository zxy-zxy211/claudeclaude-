# 银柴火 · 编导 AI 化工作 SOP v1

**这份文档干什么用**：以后所有脚本生产，只有编导本人和 AI 两个角色。按本流程走，不再临场组织指令；每次开新稿只填「标准工单」，改稿直接套「修改六步」。

版本：v1 ｜ 适用：日常脚本、全新商单、已有脚本修改
更新规则：每跑通一次发现新雷区，回来补「通用硬规则」和对应博主卡。

## 一、总览流程

两个 ⛔ 是必须本人确认的关卡，AI 不得跳过：

1. **建档（一次性）**：新博主入项，先做一张博主卡。
2. **投喂**：逐字稿 + 商单资料 + 对标链接 + 时长，一起丢给 AI。
3. **提炼**：AI 出「内容策划案」（主题 / 分论点 / 必带细节 / 可写·禁写清单 / 多版本选题）。
4. **⛔ 确认关①**：本人审主题和必带点，改完才往下。
5. **结构**：AI 给 2-3 个开头策略 + 对应结构。
6. **⛔ 确认关②**：本人定开头和结构，定了才展开。
7. **成稿**：套四段式 + 题材骨架，按 200 字/分钟出分镜表和口播稿。
8. **修改**：按「修改六步」走。
9. **落库**：更新博主卡、台账、过稿范本。

## 二、前置：新博主建档

每签一个新博主，先花一次对话把卡建出来，以后写他的稿直接调卡。

| 字段 | 填什么 |
|---|---|
| 博主名 / 平台 / 粉丝量 | 如：维佳sama / 小红书 / XX万 |
| 人设一句话 | 他是谁、给谁看、解决什么问题 |
| 说话语气 | 从过往 10-20 条作品里总结：口语节奏、口头禅、距离感、句长偏好 |
| 典型内容角度 | 他反复在讲的 2-3 个母题 |
| 雷区 / 不能说 | 他自己避讳的、平台敏感的、品牌不能碰的 |
| 过稿范本 | 1-2 条数据最好、最满意的成稿链接，作为以后改稿的对标 |
| 常用对标账号 | 记录他常参考的同赛道号 |

怎么建：把该博主过往 10-20 条作品链接（新博主用对标作品链接）一次性丢给 AI，指令：「按上面这 10-20 条作品，帮我填这张博主卡，语气和雷区要从原话里抽，不要泛泛形容。」

## 三、每次开稿：标准工单

| 项 | 内容 |
|---|---|
| 博主 | 对应一张已建好的博主卡 |
| 类型 | 人设故事 / 观点 / vlog日常 / 好物种草 / 干货 |
| 本期主题 | 可先空着，等 AI 从逐字稿提取后你审 |
| 逐字稿 | txt 直接贴或传文件 |
| 商单资料 | PDF / PPT / 产品图 / 聊天截图，有就传 |
| 对标链接 | 2-3 条同选题平台数据最高的 |
| 时长 | 按 200 字/分钟反推总字数 |

## 四、日常脚本生产流程

1. **投喂素材**：工单内容全部丢进同一个对话。商单需求从 PDF/PPT/图片里提取，不要求先整理成文字。
2. **AI 提炼【内容策划案】**：项目定位、主题、主观点 + 分论点、必带细节、可写 vs 禁写清单、2-3 个多版本选题。
   **⛔ 确认关①**：逐项看主题和必带点，改完点头 AI 才往下。
3. **AI 出 2-3 个开头策略**：每个配一条结构线。
   **⛔ 确认关②**：选定或改写开头和结构。开头优先用逐字稿里自己的原话，AI 只顺句，不重新编漂亮话。
4. **成稿**：口播稿 + 分镜表（镜号/时长/画面/口播/花字）+ 发布文案（标题+正文+TAG），严格 200 字/分钟。
5. **本人润色**：改掉书面语、AI 味、不通顺处；确认无敏感词、无隐私信息。这一步是本人，没有第二个审核人。
6. **落飞书**：按「银柴火·脚本」7 段式模板写入（基础信息 / 大纲 / 分镜表 / 文案稿 / 修改意见 / 定稿表）。

## 五、五种题材骨架

共用四段式外壳：**开头钩子 → 中段主体 → 亮点铺垫 → 结尾收口**。

| 类型 | 骨架 | 已有样例 |
|---|---|---|
| 人设故事 | 反差钩子 → 身份反转叙事 → 2-3 个真实案例砸差异 → 身份宣言收尾 | 竹嵘·大厂公关做婚礼 |
| 观点 | 反常识主观点 → 3 个分论点 → 每个配亲身故事 → 拆一个认知误区 → 金句收 | 维佳·婚商三层 |
| vlog 日常 | 爆款开头 → 时间线/事件线拆分 → 重细节和真实体验 → 情绪起伏 → 感悟金句 + 下期预告 | 肉啦马代、七岁欧洲 |
| 好物种草 | 痛点开场 → 分类法 → 每个品：是什么/戳哪痛/自用体验 → 照抄作业收尾 | Diana涓韩国、维佳七夕 |
| 干货 | 痛点引入 → 方法论拆解（N 步/N 招/N 个清单）→ 每步给具体做法 → 总结口诀 | 婚商自检清单类 |

一个项目默认拆多角度：主案例稿 + 观点人设稿 + 无旁白纯美预览片，按矩阵账号不同视角出，不一次性发完。

## 六、全新商单脚本流程

1. **吃透 brief**：商单 PDF/PPT/产品图丢进来，AI 列出必须植入的卖点、品牌关键词、时长、禁止内容，本人核对一个不漏。
2. **出框架**：套四段式生成广告脚本框架，弱化硬广感；确认品牌要求没漏、不违和博主风格。
3. **出初稿**：完整初稿，语气口语化。
4. **本人改口语**：删官方话术和行业黑话，换成博主平时的短句；核对所有卖点和关键词都在。
5. **自查**：无违规宣传、品牌信息准确、时长达标、话术自然，定稿。

## 七、脚本修改流程（六步）

1. **收集原始反馈**：保存修改意见截图，保留原话；过滤「感觉不对、一般」这类情绪词，只抓明确修改点；查是不是历史重复问题。
2. **打包发 AI**：先发意见截图（让 AI 直接读原话，避免转述走样），再发需要改的完整脚本全文。
3. **逐条核对**：拿着截图每条意见对新稿——改没改到、有没有半改/改偏、有没有 AI 自作主张增删。任一不到位就补指令再改。
4. **意见扎堆时拆单段**：多条意见指向同一段，就只截那一段的意见 + 只贴那一段原文，单独改，改完再拼回全文看衔接。
5. **全文自检**：口语度（删 AI 味）、逻辑顺不顺、和该博主过稿范例风格是否统一。
6. **交付 + 落库**：定稿标红改动位置；更新博主卡（新雷区/新口头禅）、台账、过稿范本。

## 八、通用硬规则

- **字数节奏：200 字 / 分钟。**
- 客户怀孕、具体预算、毛利率不提。
- 比价讲逻辑不报数，不用「性比价」这类空词。
- 不骂竞品，用维度差异说事。
- 分论点给满不偷工。
- 一个项目默认拆主案例稿 + 观点稿 + 无旁白预览。
- 口播要活人感，删 AI 味。
- 只交完整成品，不交草稿。
